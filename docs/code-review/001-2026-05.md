# Code Review 001 - 2026-05 Repository Audit

| Status | Date       | Project Version |
|--------|------------|-----------------|
| Draft  | 2026-05-25 | 0.0.1 |

## Scope

Review scope covered all repository text/code artifacts relevant to behavior and operations, including:

- C++ sources under source/app and source/systray
- QML and JavaScript under source/opt/cutiepi-shell
- Service and launcher scripts under source/lib and source/opt
- Build files and top-level project metadata/docs

Binary assets (images/icons) were not evaluated for code risk.

## Findings

### CR-001 - Graphics backend conflict between launcher and binary

- Severity: High
- Evidence:
  - source/opt/cutiepi-shell/cutiepi-shell:6 sets QT_QPA_PLATFORM=eglfs
  - source/app/main.cpp:74 sets QT_QPA_PLATFORM to xcb
- Impact:
  - Runtime behavior is ambiguous and environment-dependent.
  - Deployments expecting EGLFS may silently run in X11 mode.
- Recommendation:
  - Define one authoritative graphics backend.
  - Either remove the in-process override or make backend selection explicit via runtime configuration.

### CR-002 - Hard-coded runtime/user identity assumptions

- Severity: High
- Evidence:
  - source/app/main.cpp:81-82 hard-codes /run/user/1000 and DBus bus path
  - source/opt/cutiepi-shell/cutiepi-shell:3-4 hard-codes the same paths
  - source/lib/systemd/system/cutiepi-shell.service:6-7 hard-codes User=pi and /home/pi
- Impact:
  - Service startup and DBus integration can fail on systems not using user pi with UID 1000.
- Recommendation:
  - Derive runtime directory/UID dynamically.
  - Move identity assumptions to documented deployment config rather than source defaults.

### CR-003 - Local file read capability enabled for QML XHR

- Severity: High
- Evidence:
  - source/app/main.cpp:78 sets QML_XHR_ALLOW_FILE_READ to 1
- Impact:
  - Increases local file exposure risk if untrusted content reaches contexts that can issue XHR.
- Recommendation:
  - Disable by default and only enable for narrowly scoped, justified use cases.
  - Prefer explicit file loading APIs where possible.

### CR-004 - Unsafe backlight path selection by fixed index

- Severity: Medium
- Evidence:
  - source/app/backlight.cpp:10-11 uses entryInfoList() then list.at(2)
- Impact:
  - Out-of-range access risk or wrong device selection on systems with different directory contents.
- Recommendation:
  - Filter entries with QDir::NoDotAndDotDot and validate list size before indexing.

### CR-005 - Wi-Fi disconnected state typo breaks icon state mapping

- Severity: Medium
- Evidence:
  - source/opt/cutiepi-shell/shell.qml:203 checks for diconncted
  - source/opt/cutiepi-shell/NetworkManager.qml emits disconnected
- Impact:
  - UI status icon logic may never match disconnected correctly.
- Recommendation:
  - Normalize state strings and centralize them as constants.

### CR-006 - Airplane mode logic appears inverted

- Severity: Medium
- Evidence:
  - source/opt/cutiepi-shell/NetworkManager.qml:355-357
  - toggleAirplaneMode sets NetworkingEnabled to airplaneMode
- Impact:
  - Enabling airplane mode can enable networking, depending on current state.
- Recommendation:
  - Set NetworkingEnabled to !airplaneMode or rename semantics to match behavior.

### CR-007 - Startup Wi-Fi behavior relies on double toggle side effect

- Severity: Medium
- Evidence:
  - source/opt/cutiepi-shell/shell.qml:119-120 calls nm.toggleWifi() twice
- Impact:
  - Non-deterministic startup networking behavior and brittle state assumptions.
- Recommendation:
  - Replace with explicit state-setting logic that targets desired final value.

### CR-008 - Regex injection/crash risk in URL suggestion highlighting

- Severity: Medium
- Evidence:
  - source/opt/cutiepi-shell/tabControl.js:188 builds RegExp directly from user text
- Impact:
  - Certain inputs can throw regex exceptions and break suggestion rendering.
- Recommendation:
  - Escape regex metacharacters before building RegExp.

### CR-009 - Factory microphone test script uses predictable temporary file

- Severity: Low
- Evidence:
  - source/opt/cutiepi-shell/assets/mic-test.sh:4-5 uses /tmp/test.wav without cleanup
- Impact:
  - Race/collision risk and stale file leakage.
- Recommendation:
  - Use mktemp and trap cleanup.

### CR-010 - Typo in initial network state value

- Severity: Low
- Evidence:
  - source/opt/cutiepi-shell/NetworkManager.qml:9 sets unkonwn
- Impact:
  - Inconsistent state string handling and avoidable confusion during debugging.
- Recommendation:
  - Correct to unknown.

## Positive Notes

- Separation between shell UI and systray helper remains clear and maintainable.
- Backlight handling is encapsulated in a dedicated C++ class exposed cleanly to QML.
- NetworkManager integration includes callback-based DBus error logging in many paths.

## Suggested Next Review Cycle Focus

1. Implement fixes for CR-001 through CR-004 first (deployment and security-sensitive).
2. Add basic integration checks for startup state assumptions (network, backend, DBus availability).
3. Add a lightweight smoke-test checklist under docs/job-aid for field validation.

## Resolution Summary (2026-07-07)

- **CR-001**: Resolved in this working tree. `source/opt/cutiepi-shell/cutiepi-shell` no longer
  exports QT_QPA_PLATFORM, and `source/app/main.cpp` only fills in a default (eglfs) when the
  environment doesn't already set one - the systemd service's `Environment=` value is now
  authoritative. Covered by `mos-docker/tests/automated/test_cutiepi_shell_runtime_contract.py`.
  Caveat: `meta-rpi64/recipes-qt/cutiepi-shell/cutiepi-shell_git.bb` pins a different, diverged
  branch/commit of this repo for the actual compiled binary - see
  `mos-docker/docs/code-review/001-2026-07.md` (CR-001) for what that means for what really ships.
- **CR-002**: Resolved in this working tree. The service unit uses `User=root`/`WorkingDirectory=
  /root`; the launcher and `main.cpp` no longer hardcode `/run/user/1000`. Same build-vs-working-
  tree caveat as CR-001 applies - `mos-docker/docs/code-review/001-2026-07.md` found the branch the
  recipe actually pins still has `User=pi`/`WorkingDirectory=/home/pi` in its own copy of the
  service file (the separately-maintained `meta-rpi64/.../files/cutiepi-shell.service` is what
  actually carries this fix onto the deployed unit).
- **CR-003**: Resolved in this working tree. `main.cpp` only sets `QML_XHR_ALLOW_FILE_READ` when
  `CUTIEPI_QML_XHR_ALLOW_FILE_READ` is explicitly set, and calls `qunsetenv` otherwise.
- **CR-009**: Resolved. `assets/mic-test.sh` now uses `mktemp`+`trap` for its recording file (no
  more predictable `/tmp/test.wav`), and also picks up the default PulseAudio source instead of a
  hardcoded index and restores the original volume on exit (found during the same pass that
  produced `mos-docker/docs/code-review/001-2026-07.md`, CR-005 there).
- CR-004 through CR-008 and CR-010 were not touched in this pass and remain open.
